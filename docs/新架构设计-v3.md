# 配音工作流新架构 v3

## 目标

系统只保留两个顶层目录：

```text
配音工作区\
├─ 声音本体\
└─ 项目文件夹\
```

声音本体是工具和索引中心，项目文件夹是真实业务资料中心。两者不混放真实素材，Codex 通过快捷方式把当前任务需要的文件暴露到对应位置。

## 一、声音本体

声音本体只允许存放可复用的程序、Skills、配置模板、任务索引和运行日志，不允许存放任何原始音频、视频、提示词、生成视频、MP3 或项目成品。

建议结构：

```text
声音本体\
├─ 01_程序与工具\
│  ├─ Skills\
│  ├─ 脚本\
│  ├─ 配音任务看板.exe\
│  ├─ Seedance API配置工具.exe\
│  └─ CC Switch\
├─ 02_任务索引\
│  ├─ 项目索引.json
│  ├─ 任务索引.json
│  └─ 项目快捷方式索引.json
├─ 03_运行日志\
│  ├─ 总任务日志.jsonl
│  └─ 问题汇总.md
└─ 04_模板与规范\
   ├─ 任务索引模板.json
   ├─ 项目配置模板.json
   └─ 工作流规范.md
```

### 声音本体禁止项

- 禁止存放角色音色素材。
- 禁止存放剧本、台词正文和完整提示词。
- 禁止存放生成视频、MP3 或交付成品。
- 禁止把项目临时文件复制到本体；只能创建快捷方式或写入短索引。

## 二、项目文件夹

项目文件夹按剧集、项目或客户任务拆分。每个项目拥有全部真实资料，但不复制工具本体：

```text
项目文件夹\
├─ 项目注册表.json
├─ 项目A\
│  ├─ 01_输入资料\
│  │  ├─ 01_角色音色素材\
│  │  ├─ 02_剧本与剧情\
│  │  ├─ 03_台词任务\
│  │  └─ 04_临时素材\
│  ├─ 02_生产成品\
│  │  ├─ 01_生成视频\
│  │  └─ 02_MP3\
│  ├─ 03_交付与版本\
│  │  ├─ 01_待提交\
│  │  ├─ 02_工作版本\
│  │  └─ 03_历史版本\
│  ├─ 04_管理与记录\
│  │  ├─ 01_API配置\
│  │  ├─ 02_任务日志\
│  │  ├─ 03_问题与改进\
│  │  └─ 04_快捷方式\
│  └─ .codex\
│     ├─ 项目状态.json
│     ├─ 任务清单\
│     ├─ 对话路由.json
│     └─ 快捷方式清单.json
└─ 项目B\
```

`.codex` 只存结构化状态、20-30 字任务摘要、路径索引、对话租约和改动记录，不存大体积素材。

## 三、快捷方式边界

快捷方式是两个目录之间唯一的文件交换方式。真实文件永远只存在项目文件夹；声音本体和工作 Chat 只通过快捷方式读取或写入被授权的项目位置。

### 项目指向声音本体

项目内建立：

```text
项目\04_管理与记录\04_快捷方式\声音本体工具.lnk
项目\.codex\快捷方式\工具\
```

它只能指向声音本体的程序、Skills 和模板目录，不得指向声音本体的素材文件。

### 声音本体指向项目资料

声音本体为当前任务建立临时快捷方式集合：

```text
声音本体\当前项目\项目A\
├─ 输入_角色音色.lnk
├─ 输入_台词任务.lnk
├─ 输出_生成视频.lnk
└─ 输出_MP3.lnk
```

任务结束或切换项目时，删除旧的临时快捷方式并重新生成，防止跨项目误读。

### 快捷方式安全规则

- 创建前必须记录 `source_path`、`link_path`、`project_id`、`task_id` 和 `purpose`。
- 只允许指向当前选中的项目；项目不明确时不能创建。
- 不允许把快捷方式指向服务器或 UNC 路径，除非用户明确批准。
- 删除快捷方式不删除目标真实文件。
- 每次创建、更新、删除都追加到项目日志和声音本体运行日志。

## 四、任务索引

每条任务只在声音本体和项目 `.codex` 中保留短索引，不复制正文素材：

```json
{
  "task_id": "0725001_03",
  "project_id": "末日远征队",
  "summary": "月儿回答姐姐，语速略慢并保留关切感",
  "summary_max_chars": 30,
  "status": "待理解",
  "source_project": "D:\\项目文件夹\\末日远征队",
  "source_task_json": "D:\\项目文件夹\\末日远征队\\01_输入资料\\03_台词任务\\0725001+任务.json",
  "selected_material_links": [],
  "output_links": [],
  "owner_chat": "任务理解与分配",
  "last_error": null,
  "updated_at": null
}
```

`summary` 只能写 20-30 字以内的人工可读摘要；完整台词、提示词和媒体路径留在项目真实文件中，通过索引和快捷方式关联。

## 五、项目识别

所有任务开始前，入口 Chat 必须确认：

1. 当前工作区路径。
2. 当前项目 ID 和项目名称。
3. 当前任务 ID；如果用户只给文件名但无法唯一识别项目，必须询问。
4. 任务 JSON 的真实路径和角色音色素材路径。
5. 当前快捷方式集合是否仍指向同一项目。

如果同时存在多个项目候选，禁止根据最近修改时间、文件名相似度或旧对话猜测。只能向用户询问“要处理哪个项目/任务”。

## 六、统一对话架构

用户只与一个入口对话交互，名称固定为：`任务理解与分配`。

入口负责理解需求、识别项目、建立任务短索引、选择素材、创建快捷方式、分派工作、汇总结果和向用户反馈。

内部可存在以下协作 Chat，但用户不向它们发送信息，也不接受它们的直接反馈：

```text
任务理解与分配
├─ 提示词
├─ 生成
├─ 监控
├─ 拉回
└─ 记录
```

### 单向反馈规则

- 所有下属 Chat 的正常结果必须回传 `任务理解与分配`。
- 所有错误、余额不足、权限问题、项目不明、文件缺失、快捷方式失效和模型不一致，必须立即回传 `任务理解与分配`。
- 下属 Chat 不得把错误只写在自己的聊天框后结束。
- 下属 Chat 不得要求用户确认或直接向用户提问。
- 入口收到错误后暂停后续派发，向用户说明问题并等待用户决定。
- 只有入口 Chat 可以向用户发送反馈，也只有入口 Chat 可以恢复流程。
- `记录` Chat 可以写日志，但完成后仍要把成功或失败结果交回入口；“单向终止”只表示不再向下游派发，不表示吞掉错误。

## 七、统一任务循环

```text
用户 -> 任务理解与分配
     -> 识别项目与任务
     -> 创建/校验快捷方式
     -> 建立20-30字任务索引
     -> 提示词
     -> 生成
     -> 监控
     -> 拉回
     -> 记录
     -> 任务理解与分配
     -> 用户
```

入口 Chat 每次收到下属结果后都要：

1. 校验返回的 `project_id` 和 `task_id`。
2. 校验所有路径仍在当前项目根目录下。
3. 更新声音本体短索引和项目 `.codex` 索引。
4. 记录成功、失败、重试和用户反馈。
5. 只有在结果完整且没有错误时，才派发下一个阶段。

## 八、迁移原则

这份设计只定义新架构，不自动移动旧生产资料。迁移时必须：

1. 先建立完整路径清单和备份。
2. 创建项目文件夹和声音本体目录。
3. 复制工具到声音本体；真实素材只移动或复制到项目文件夹。
4. 为工具、输入和输出创建快捷方式。
5. 生成短任务索引并反查每条台词的真实位置。
6. 运行空任务验证快捷方式、项目识别和错误回传。
7. 用户确认后，才迁移真实生产文件。

在用户确认迁移前，不删除、覆盖或重命名现有 `D:\配音文件夹` 中的任何文件。

## 九、更新原则

普通更新由 Codex 从已登记的官方 GitHub Release 自动拉取并校验所需工具。已有素材的归位采用非破坏方式：只在新分类目录建立快捷方式和路径索引，原文件保持原路径、文件名和内容不变。更新器在本地维护受保护路径清单并做前后比对；素材、提示词、视频、MP3、日志、交付版本、API 私有配置和 `.codex` 任务记录发生变化时立即中止更新。

官方 Skills 与用户 Skills 永久分离。官方 Skills 与官网保持一致，更新时允许覆盖本地官方副本；用户 Skills 位于 `声音本体\01_程序与工具\用户Skills`，可按 `全局`、`角色`、`分任务` 分类，更新绝不覆盖。仅本次 `20260813` 更新先把源文件夹改名为 `源文件夹-旧`，再复制出同名工作副本并在副本上分离。
