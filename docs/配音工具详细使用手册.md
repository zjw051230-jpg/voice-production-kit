# 配音工具详细使用手册 v2.1

## 阅读路径

这份手册按实际工作分成三条路径，不需要第一次就从头背到尾：

- **第一次使用**：先读第 1～7 节，完成安装、API、CC Switch、项目和六个 Chat 初始化。
- **日常生产**：读第 8～14 节，按“台词资料 → 提示词 → 生成 → 监控 → 拉回 → 记录”工作。
- **故障处理**：直接看第 15～24 节，根据看板状态、API、文件或对话问题定位。

用户只需要向 Codex 说明目标并提供资料；目录、索引和程序状态由 Codex 管理。密钥只在本机程序中填写，服务器复制必须另行批准。

## 1. 这套工具包含什么

- 多项目配音文件系统。
- 七个 Codex 配音工作流 skill。
- Seedance 配音视频生成、监控、下载和 MP3 提取工具。
- 原生 Windows 配音任务看板。
- 原生 Windows Seedance API 配置工具。
- CC Switch 3.18.0 程序本体。
- CC Switch `5.5 -> dpskv4` 专用安全映射工具。

安装包不包含真实 API Key、CC Switch 用户数据库、生产素材或 `D:\codex-board`。

## 2. 新电脑安装

把整个 `安装包\v2.1` 文件夹交给 Codex，说：

```text
请完整读取 START-HERE.md，安装这套配音工具，并创建我的第一个项目。安装过程中不要调用付费 API，不要上传素材。
```

Codex 会询问工作区路径和项目名。建议工作区放本机数据盘，例如 `D:\配音工作区`，不要默认放服务器。

安装完成后桌面会出现：

- `CC Switch`
- `配音任务看板`
- `Seedance API配置工具`

已有不同版本的 CC Switch 或同名 skill 时默认保留。只有用户明确批准后，Codex 才能用 `-Force` 先备份再替换。

## 3. 创建项目

如果需要创建项目，直接对 Codex 说：

```text
我要创建项目，名字叫“XXX”。
```

把 `XXX` 换成实际项目名。Codex 会继续询问工作区位置、剧本、台词、角色音色和 API 是否已经准备好，然后自动创建并管理完整项目目录，不需要用户手工建立文件夹。

## 4. 配置 Seedance API

双击桌面的 `Seedance API配置工具`，或打开项目 `04_管理与记录\01_API配置\Seedance API配置工具.exe`。这个程序是本机窗口，不需要浏览器，也不会在配置阶段访问网络。

1. 在“项目”下拉框中选择要配置的项目。
2. 选择 `test版` 或 `正式版`。正式地址为 `https://chat.q1.com/v1`，test 地址为 `https://chat-test.q1.com/v1`。
3. 在遮罩输入框中填入一份 API Key，点“添加 API”。程序立即写入磁盘；多份密钥就重复添加，重复项自动忽略。
4. 在列表中选中优先使用的一份，点“设为当前”。删除和设为当前都会立即同步磁盘。
5. 底部“保存并生成配置”始终可见，用于手动确认或写入失败后的重试。

程序自动整理：

```text
项目\apis\
├─ doubao_api_config.json        当前活动配置
└─ api_pool\
   ├─ index.json                 不含密钥的索引
   ├─ test\                     test版配置池
   └─ production\               正式版配置池
```

有多份 API 时自动编号、去重和建立索引。列表只显示本地编号和不可逆指纹尾号，不显示完整密钥。隐藏 `.codex\04_API池与余额切换.md` 记录线路、配置数量、当前项和余额事件，但不记录 API Key。

再次保存时，被删除或替换的旧配置不会继续参与轮换，程序会自动移入 `apis\api_pool\_archive`。API Key 只保存在所选项目的私有配置 JSON 中，不进入聊天、日志、索引或说明文档。

原 `.codex-tools\配置Seedance API.ps1` 仍保留。无参数运行时启动桌面程序；显式传参时可继续从 CC Switch provider 数据库批量导入。

可直接对 Codex 说：

```text
打开 Seedance API配置工具，让我在本机选择项目和线路并录入 API，不要显示或记录任何密钥。
```

只有用户明确要求实际生成时才调用付费 API。

## 5. 配置 CC Switch

1. 打开桌面的 `CC Switch`。
2. 进入 Codex provider 管理区域。
3. 新建或选中要使用的 provider。
4. 在 CC Switch 界面本地填写 API 地址和密钥。
5. 保存并将它设置为当前 Codex provider。
6. 完全退出 CC Switch，包括系统托盘。
7. 保持 Codex 当前对话打开，把下一节的固定指令发给 Codex。

API Key 只填写在 CC Switch 界面，不要粘贴给 Codex。

## 6. 只映射 5.5 到 dpskv4

复制整段发送给 Codex：

```text
我已经在 CC Switch 中完成 Codex provider 和 API 配置，并已完全退出 CC Switch。请读取当前 v2.1 安装包中的“API与CCSwitch配置.md”，使用 scripts\configure_ccswitch_model.py 处理当前 Codex provider。只允许新增或修改显示名严格等于“5.5”的这一条映射，使它实际请求“dpskv4”；绝对禁止修改、重命名、删除或映射任何其他模型，也不得修改 API Key、base_url、provider ID 或其他数据库表。先执行 dry-run，只有预览明确显示“5.5 -> dpskv4”且显示其他模型未改变时，才自动备份数据库并执行修改；随后运行数据库完整性检查，报告 provider 名称和 ID、备份路径、映射结果与检查结果。完成后停止，不做其他操作。
```

必须看到 Codex 报告：

- provider 名称和 ID。
- `5.5 -> dpskv4`。
- 其他模型未改变。
- 数据库备份路径。
- `integrity_check: ok`。

绝对不能把任何 `5.6` 系列或其他模型映射到 `dpskv4`。

映射完成后：

1. 关闭 Codex。
2. 打开 CC Switch，重新应用刚才的 provider。
3. 启动 Codex。
4. 选择界面显示的 `5.5`。
5. 发一条无敏感信息的测试消息。
6. 在 CC Switch 日志确认真实请求模型是 `dpskv4`。

## 7. 创建配音项目

对 Codex 说：

```text
创建一个配音项目，项目名是“项目名”。先检查我缺少哪些剧本、台词、角色音色和 API 配置，再创建目录和索引。
```

Codex 应逐项确认：剧本、角色名、角色音色素材版本、台词、时长、情绪、生成版本数、API 是否就绪和本地交付位置。

首次进入项目时，入口必须命名为 `理解文本与任务`，并创建 `提示词`、`生成`、`监控`、`拉回`、`记录` 五个独立 Codex 任务。六个任务必须使用各自的模型、提示词和互不重复的 thread ID，并逐个验证完全访问权限。入口执行 `bootstrap-status` 返回 `ready=true` 后才能派发第一条业务任务；入口不得自己代做下游五个阶段。

创建每个Chat时，主对话必须把下面这句话作为第一条消息发送：

```text
这个对话开启完全访问，不需要问我要任何的批准。
```

随后由该Chat亲自运行 `manage_chat_workflow.py verify-access`。成功完成写入、读回和删除探测后才算通过权限门禁，主对话不能代验，也不能只手改JSON。如果仍反复出现批准提示，先在该任务界面底部把权限切换为“完全访问”，再手动发送上面这句话并重新运行探测。聊天文字本身不能绕过Codex应用、Windows或组织策略；实际权限设置才是生效依据。

每次派发前运行 `prepare-handoff`。成功时脚本会把目标标为忙碌，写入 `active_task` 并返回唯一 `lease_id`；下属Chat完成时必须携带同一租约运行 `complete`。主对话发送任务后立即停止继续处理，使用Codex任务等待功能等待该Chat反馈；收到反馈并运行 `ack-feedback` 后才能恢复。这样可以避免主对话空转，也能防止旧任务错误清空新任务。

如果目标Chat不空闲，不要发送第二条。脚本会返回 `timer_required=true` 和 `retry_contract`，主对话按合同建立5分钟单次定时器，到点只重试原来的交接；若仍忙，再按新合同继续等待。不得并行向同一Chat塞入两项任务，也不得手改status绕过租约。

`记录` Chat 是单向终止阶段，不参与反馈循环。它只写问题改进和逐句改动记录，禁止向主线程或其他Chat发送消息，也不能继续交接任务。记录完成时只用当前 `lease_id` 运行 `complete`，不会生成 `feedback_contract`。主对话看到 `one_way_terminal=true` 后明确知道无需等待记录反馈，派发后直接结束本轮。

## 8. 准备任务 JSON

任务放入项目的 `文字素材` 或 `01_输入资料\03_配音任务`。标准字段：

```json
{
  "剧本名字": "剧本名",
  "task_ID": "任务ID_1",
  "角色名字": "角色名",
  "台词": "只说这一句台词。",
  "时长": "4秒",
  "提示词": "音色、情绪、语速、重音和只能说指定台词的要求"
}
```

角色参考素材放在 `角色音色素材\剧本名\角色名`。没有额外选择规则时，音频和视频素材全部作为参考上传；每次请求必须带视频参考。

## 9. 写提示词

对 Codex 说：

```text
读取这个任务 JSON 和对应剧本，按剧情情绪写 Seedance 配音提示词。音色必须参考指定角色，只允许说 JSON 中的台词，不能改字、漏字或增加别的话。
```

提示词应明确音色、年龄感、口音、情绪、语速、停顿、重音、句尾、台词唯一性和禁止旁白/音乐/第二人声。

## 10. 提交生成

对 Codex 说：

```text
用 sdc 提交这个任务。按 JSON 时长，未规定时用 4 秒；480p、9:16；每句生成 4 版；并行提交。拿到全部远端任务 ID 后停止。
```

Codex 应保存远端 ID 和状态文件。多个任务并行，不要串行等待；不得因查询超时重复提交。

## 11. 监控与拉回

监控：

```text
只查询已有任务状态，不重新提交、不上传、不下载。报告成功、失败、运行中和总数；只有成功数加失败数等于总数时才通知拉回。
```

拉回：

```text
确认整批任务已经满足“成功数 + 失败数 = 总数”后，把全部成功视频拉回对应项目，并按任务要求直接转 MP3 或裁剪后转 MP3。不要重新提交；失败版本只保留记录。
```

监控只运行 `--resume-only --monitor-only --poll-once`，因此不会提前下载局部成功结果。达到整批终态后，监控把 `.seedance-state.json` 交给拉回 Chat；交接脚本先检查一次，拉回命令 `--resume-only --pullback-only` 再检查一次。任意一处发现仍有运行任务都必须停止拉回。

未要求裁剪时，直接从完整视频提取 MP3。要求只保留台词时，再按具体留白要求裁剪。

## 12. 余额不足自动切换

如果任一 Chat 或 Seedance 流水线发现明确余额不足：

1. 立即停止所有提交、监控和拉回。
2. 自动把所有 Chat 状态设为0，只把 `理解文本与任务` 设为1。
3. 把紧急消息发给 `理解文本与任务` 的thread ID。
4. API池有下一份时自动切换；没有时让用户在CC Switch中增加新API，再重新导入。
5. `理解文本与任务` 恢复后使用原参数重新提交，不加 `--force-regenerate`。
6. 已有远端ID的版本自动跳过，只重提余额失败或尚未提交的版本。

项目隐藏文件 `.codex\04_API池状态.json` 是所有Chat的暂停门禁；暂停期间其他Chat不得继续工作。

## 13. 使用配音任务看板

双击桌面的 `配音任务看板`。看板自动汇总工作区所有项目并显示任务状态和进度。

看板进度同时显示终态、成功、失败、运行中和已下载数量。即使已有失败版本，只要还有运行版本就保持“生成中”；整批终态后显示“可拉回”“已结束（含失败）”或“已结束（全部失败）”。至少一个版本成功且所有成功版本均已下载后才显示：

- `成品链接`：打开输出目录。
- `复制到地址`：输入目标地址后复制成品。

目标地址不能包含双引号。复制操作只复制、不移动、不删除、不覆盖。

## 14. 返工与问题记录

发现台词、音色、情绪、噪声或裁剪问题时，对 Codex 说清楚具体版本和修改要求。Codex 只重做有问题的版本，并把问题追加到项目 `问题与改进log\问题建议.md`。

不要覆盖用户要求保留的旧版。没有用户批准，不得把文件复制到服务器。

## 15. 常见故障

- API `401/403`：检查密钥、权限和余额。
- 上传 `404`：上传接口不能拼在 `/v1` 后面。
- API `422`：检查字段类型、时长、画幅和参考素材 URL。
- CC Switch 找不到 `5.5`：重新应用 provider，再重启 Codex。
- `5.5` 未请求 `dpskv4`：检查是否存在旧代理脚本的第二层改写，先回滚再排查。
- 看板路径错误：让 Codex 使用 `repair-voice-dashboard` skill 检查工作区、快捷方式和权限。

## 16. CC Switch 回滚

映射脚本会把修改前数据库备份到：

```text
%USERPROFILE%\.cc-switch\backups
```

回滚前完全退出 Codex 和 CC Switch，将对应 `cc-switch.before-model-map.<时间>.db` 恢复为 `cc-switch.db`，再启动 CC Switch、重新应用 provider，最后启动 Codex。

## 17. 核心术语

| 名称 | 含义 |
| --- | --- |
| 工作区 | 存放多个配音项目的总目录，根目录有 `项目注册表.json` |
| 项目 | 一部剧或一组独立交付内容，内部固定为四个主要目录 |
| task_ID | 一句台词的稳定编号，提示词、远端任务、视频、MP3 和返工都靠它关联 |
| 版本 | 同一句台词的一次生成结果，通常写作 `v01`、`v02` |
| 远端 ID | Seedance 接受请求后返回的任务编号；已有远端 ID 时不得重复提交 |
| 状态文件 | `.seedance-state.json`，记录每个版本的远端状态、输出路径和错误 |
| 整批终态 | `成功数 + 失败数 = 总数`，这是通知拉回的唯一条件 |
| 成品完整 | 整批终态、至少一版成功，而且每个成功版本的视频与 MP3 都实际存在 |
| 完全访问 | Codex 任务实际具备所需本机读写权限；聊天中的一句话不能替代应用权限设置 |
| 租约 | 主任务派发给下属 Chat 时产生的唯一 `lease_id`，防止旧任务清掉新任务状态 |

## 18. 第一次使用检查清单

安装前确认：

- Windows 本机有可写的数据盘目录，不把工作区直接设为共享服务器。
- Python 3.10 或更高版本可用，`ffmpeg` 可用于提取音轨。
- 安装包文件完整；不包含真实密钥、生产素材、用户数据库或 `D:\codex-board`。
- 安装时没有运行会占用目标 EXE 的旧看板或 API 配置工具。

安装后确认：

- 桌面存在 `配音任务看板`、`Seedance API配置工具` 和 `CC Switch` 三个入口。
- 工作区存在 `项目注册表.json`，项目下能看到四个主要目录。
- 项目的 `.codex` 是隐藏管理目录，旧目录映射仍存在且没有被手工解除。
- API 配置工具选中项目后，添加、删除和“设为当前”都会立即写盘。
- 看板能读取项目，顶部显示任务总数和阶段统计，而不是空白或指向旧盘符。
- 六个 Chat 的 thread ID 互不重复，模型、思考程度和访问探测均符合合同。

任何一项不通过时先停止生产，不要用真实任务试错。可对 Codex 说：

```text
检查当前 v2.1 配音工具的安装、工作区注册、三个桌面程序和六Chat门禁。只做本机离线检查，不调用Seedance、不上传素材、不修改媒体文件。
```

## 19. 六个 Chat 的职责和反馈关系

| Chat | 负责什么 | 不负责什么 | 完成后去向 |
| --- | --- | --- | --- |
| 理解文本与任务 | 询问资料、拆分任务、维护索引、选择下游合同、汇总反馈 | 不代写提示词、不生成、不监控、不拉回 | 派发到提示词，收到反馈后继续 |
| 提示词 | 读取剧本、角色和台词，写入标准 JSON | 不提交付费生成 | 反馈给理解文本与任务 |
| 生成 | 校验素材和 API，并行提交，保存全部远端 ID | 不长时间轮询、不拉回 | 反馈给理解文本与任务 |
| 监控 | 每次只查一次已有远端状态，判断整批终态 | 不重提、不上传、不下载局部结果 | 终态后交给拉回，否则继续定时查询 |
| 拉回 | 二次检查整批终态，下载成功视频并生成 MP3 | 不重新提交，不为失败版本伪造成品 | 反馈给理解文本与任务 |
| 记录 | 追加逐句改动和问题改进记录 | 不向主任务汇报，不再交接 | 单向结束 |

主任务创建或派发下属 Chat 时，必须显式使用脚本返回的模型和思考程度，不能省略后让界面自行选择默认模型。第一条初始化消息固定包含：

```text
这个对话开启完全访问，不需要问我要任何的批准。请按派发合同使用指定模型和思考程度，并先完成权限探测；做完当前租约后把status设回0。
```

如果应用仍反复询问批准，用户需要在该任务界面底部手动选择“完全访问”，再发送上面的初始化消息。是否真正生效，以 `verify-access` 的写入、读回和删除探测结果为准。

主任务派发后必须停止继续做该阶段，等待对应 Chat 的反馈。目标 Chat 已忙时不得再塞第二项任务，应按脚本返回的合同创建 5 分钟单次定时器；到点只重试原交接。记录 Chat 是唯一例外，它不反馈，主任务派发后直接结束本轮。

## 20. 日常生产标准话术

### 建立项目

```text
我要创建项目，名字叫“项目名”。请先问我工作区、剧本、台词来源、角色音色版本、API状态、默认生成规格和本地交付位置，再创建目录与索引。不要把文件放到服务器。
```

### 整理台词并写提示词

```text
读取这个剧本和任务JSON，只处理未开始的台词。根据剧情补足情绪、语速、停顿、重音和句尾；指定角色只复刻已选中的音色；唯一允许说的内容必须与台词字段逐字一致。写完JSON后停止，不提交生成。
```

### 提交 Seedance

```text
用sdc提交这个任务JSON。每句按JSON时长，缺省4秒，480p、9:16，每句并行生成4版。使用已选中的音视频参考，每次必须上传视频参考。保存全部远端ID和状态文件，拿到ID后停止，不轮询、不拉回。
```

### 监控

```text
只对已有远端ID执行一次状态查询。不得重新提交、不得上传、不得使用force regenerate、不得下载。报告总数、成功、失败和运行中；只有成功加失败等于总数时才能通知拉回。
```

### 拉回

```text
先从状态文件确认整批满足成功数加失败数等于总数。满足后只下载全部成功版本，保存到对应项目并按任务要求生成同名MP3；不满足就停止。不要重新提交，不要给失败版本创建空文件。
```

### 返工

```text
只返工我指出的task_ID和版本。先根据索引找回原台词、提示词、参考素材和来源文件；保留正确部分，只修改我反馈的问题。新版本不要覆盖旧版，并把原因和改动追加到该台词的改动记录。
```

## 21. 看板状态说明

看板把底层技术状态归成五个阶段，筛选框只显示这些阶段；卡片仍保留精确状态、计数和下一步。

| 阶段 | 精确状态 | 含义 | 建议操作 |
| --- | --- | --- | --- |
| 准备中 | 素材未登记 | 角色没有素材记录 | 登记角色素材 |
| 准备中 | 素材缺失 | 已确认角色没有可用素材 | 补充角色素材 |
| 准备中 | 素材待选择 | 有多版素材但尚未选定 | 确认参考音色 |
| 准备中 | 待准备 / 提示词就绪 | 尚缺资料，或已可提交 | 补齐资料或提交生成 |
| 生产中 | 已提交 / 生成中 | 已有远端任务但整批未终态 | 等待监控，不重复提交 |
| 待拉回 | 可拉回 | 整批终态且至少一版成功，但成功成品未全部落地 | 拉回全部成功版本 |
| 需处理 | 成品缺失 | 状态写着已下载，但本地视频或 MP3 不存在 | 检查路径或重新拉回 |
| 需处理 | 拉回失败 | 下载或后处理失败 | 重试拉回 |
| 需处理 | 已结束（全部失败） | 所有远端版本都失败 | 调整后重做 |
| 已交付 | 已结束（含失败） | 成功成品完整，同时有失败版本 | 可交付，并检查是否补做失败版 |
| 已交付 | 已完成 | 全部成功成品完整 | 打开或复制成品 |

看板不会再用“素材缺失”覆盖已有远端任务的真实状态。`downloaded` 只是状态记录；本地视频和 MP3 都存在才计入“已下载”。顶部“需处理”可与“已交付”重叠，例如一条含失败但已有完整成功成品的任务既可交付，也值得检查失败版本。

卡片显示 task_ID、项目、剧本、角色、时长、素材状态、最近更新时间、来源 JSON、台词、终态/成功/失败/运行中/已下载五项计数和下一步。搜索可匹配台词、角色、状态、下一步或来源文件。

## 22. 交付检查清单

点击“成品链接”或复制前，逐项确认：

- 看板处于“已交付”，整批远端状态已经终态。
- 至少一版成功；每个成功版本的 MP4 和 MP3 都能实际打开。
- 台词逐字正确，没有漏词、改词、续说或不应出现的第二人声。
- 音色、年龄感、口音、语速和情绪符合角色与剧情。
- 需要裁剪的任务已经按要求保留前后留白；不要求裁剪的没有误裁。
- 文件名包含正确 task_ID、角色、台词和版本号，索引能追溯到来源 JSON。
- 失败版本已记录，但不会阻止已有成功成品交付。
- 目标地址正确，不含双引号，且目标任务文件夹尚不存在。
- 复制是用户在弹窗中按“提交并复制”触发的；未经批准没有复制到服务器或共享目录。

## 23. 故障处理决策表

| 现象 | 先检查 | 正确处理 | 禁止操作 |
| --- | --- | --- | --- |
| 看板没有项目 | 工作区是否有 `项目注册表.json` | 重新选择正确工作区或运行修复 skill | 手改成未知绝对路径 |
| 看板显示素材未登记 | `.codex\01_素材状态与选用.json` | 同步任务清单并登记角色素材 | 有远端任务时重新提交 |
| 看板显示成品缺失 | 状态文件中的 `output`、`mp3` 路径 | 找回文件或执行只拉回 | 创建空 MP3 冒充成品 |
| 监控长期运行 | 远端 ID、API 状态、最后更新时间 | 每次只查一次，并按定时器继续 | 无远端 ID 就强制重生 |
| 成功和失败未到总数 | 是否仍有 queued/processing | 继续等待，不能通知拉回 | 提前下载局部结果 |
| API 余额不足 | `.codex\04_API池状态.json` | 全局暂停，通知理解文本与任务，切换备用 API | 让各 Chat 各自重提 |
| API 返回 401/403 | 当前线路、密钥有效性、权限 | 在本机 API 工具更新，不在聊天中发密钥 | 把密钥写进日志或 Git |
| CC Switch 映射异常 | 当前 provider 和 dry-run 输出 | 只修复精确 `5.5 -> dpskv4`，必要时回滚数据库 | 修改 5.6 或其他模型 |
| 下属 Chat 一直忙 | `active_task` 和 `lease_id` | 5 分钟后重试同一交接 | 同时发送第二项任务 |
| Chat 总问批准 | 应用底部权限与 verify-access | 手动选择完全访问后重新探测 | 只靠聊天文字声称已授权 |
| 台词或情绪错误 | task_ID、版本、来源提示词 | 只返工错误版本并追加记录 | 覆盖正确旧版 |
| 复制按钮拒绝目标 | 地址、双引号、同名目标目录 | 改为有效空目标位置 | 覆盖或移动原成品 |

## 24. 备份、迁移与安全边界

迁移到新电脑时，优先复制工作区本体和安装包，不复制正在运行的临时文件。迁移后让 Codex重新检查项目注册表、目录联接、看板配置和快捷方式。盘符变化时使用修复 skill 更新配置，不要批量替换媒体文件内部数据。

建议备份：项目的四个主要目录、项目注册表、`.codex` 任务索引和必要的本地 API 配置。API 配置备份必须按组织安全要求保存；不要提交到 GitHub。CC Switch 数据库只能在完全退出 Codex 与 CC Switch 后备份或恢复。

以下内容不得进入公开安装包或仓库：API Key、访问令牌、真实 `cc-switch.db`、provider 私有数据、生产音视频、远端任务运行状态、个人桌面路径、共享服务器凭据和 `D:\codex-board`。本工具默认只在本机工作；任何向 UNC 路径或服务器的复制都必须得到用户明确批准。

## 25. FAQ

**可以一个 Chat 做完整流程吗？**

不可以。v2.1 强制入口加五个下属 Chat 分工，门禁未完成时生产脚本应停止。

**为什么生成成功后不马上下载？**

因为一批任务可能还有运行版本。只有 `成功 + 失败 = 总数` 后才交给拉回，避免提前下载、重复工作或漏掉版本。

**有一版失败，成功成品还能交付吗？**

可以。只要整批终态、至少一版成功，并且所有成功版本的 MP4 与 MP3 都实际存在，看板会显示成品按钮，同时提示检查失败版本。

**为什么看板显示“成品缺失”？**

状态文件记录为 `downloaded`，但登记的 MP4 或 MP3 在本地找不到。应检查盘符、移动记录或重新拉回，不能用空文件绕过。

**我能直接把 API Key 发给 Codex 吗？**

不能。密钥只在 Seedance API 配置工具或 CC Switch 本机界面输入，聊天、日志、手册和 Git 都不保存明文。

**“开启完全访问”一句话一定生效吗？**

不一定。它是初始化提示，不会越过 Codex 应用、Windows 或组织策略。实际结果以界面权限和 `verify-access` 探测为准。
