# 配音工作流工具 v2.1 首次安装说明

> 历史文档。v2.2 当前安装入口是 `START-HERE.md`；环境工具必须通过独立 `env4BC` 安装。

适用对象：新电脑，或从未安装过本工具的 Windows 用户
GitHub：<https://github.com/zjw051230-jpg/voice-production-toolkit4bingchuan>
版本分支：`develop/v2.1`

## 不适用情况

如果电脑上已经存在以下任意内容，不要按首次安装处理：

- 已安装的 v2.0 或其他旧版本配音工具。
- 已有配音工作区和 `项目注册表.json`。
- 已有本工具创建的七个 Skills。
- 已有需要保留的 CC Switch 配音 provider 或项目隐藏 `.codex` 状态。

这类情况请改用 [v2.1更新公告.md](v2.1更新公告.md)，执行 v2.0 到 v2.1 原地升级。

## 安装前准备

- Windows 10 或 Windows 11。
- Codex 桌面应用。
- 本机普通磁盘上的安装包或 GitHub 仓库。
- 一个准备存放多个配音项目的本地工作区路径，例如 `D:\配音工作区`。
- 第一个项目名称。
- 后续需要在本机界面填写的 Seedance API Key 和 CC Switch provider 信息。密钥不要发送到聊天。

推荐下载并解压 `配音工具安装包_v2.1.zip`。也可以从 GitHub 的 `develop/v2.1` 分支取得源码。不要把工作区或安装包放在服务器、UNC 路径或网络共享目录。

## 用户需要做什么

1. 打开 Codex，并把当前任务权限切换为“完全访问”。聊天文字不能代替界面权限设置。
2. 把安装包放到本机目录。
3. 准备工作区路径和第一个项目名。
4. 将下一节的完整字段发送给 Codex。
5. Codex 打开 API 配置工具和 CC Switch 时，在本机窗口中填写密钥；不要粘贴到聊天。
6. 安装完成后，按照 Codex 报告重启一次 Codex。只有 CC Switch 程序本体刚安装或替换时，才重启一次 CC Switch。

## 发给 Codex 的完整首次安装指令

复制下面整个字段，原样发送给 Codex：

```text
请在这台 Windows 电脑上首次安装“配音工作流工具 v2.1”，创建本机多项目工作区和第一个项目，并完成离线验证。开始前先确认这是真正的首次安装；如果发现 v2.0、其他旧版本、已有项目注册表或需要保留的配音项目，立即停止并改用 v2.0 到 v2.1 升级流程。

安装来源优先级：
1. 优先使用我已经放在本机的“配音工具安装包_v2.1.zip”或解压后的 v2.1 安装包。
2. 本机没有安装包时，从下面公开仓库取得 develop/v2.1：
https://github.com/zjw051230-jpg/voice-production-toolkit4bingchuan

必须遵守以下边界：
1. 不要让我在聊天中提供或显示任何 API Key。
2. 不得把安装包、工作区、项目、素材或配置放到服务器、UNC 路径或网络共享目录。
3. 不得创建、复制或修改 D:\codex-board。
4. 安装和验证期间不得调用 Seedance 或其他付费生成 API，不得上传任何素材。
5. 不得创建“默认项目”“测试项目”“项目1”等猜测名称；工作区路径或第一个项目名未给出时，只向我询问这两个值。
6. 不得声称聊天文字可以绕过 Codex、Windows 或组织权限。先实际检查完全访问；权限不足时让我在 Codex 界面底部切换后再继续。
7. API Key 只能由我在 Seedance API配置工具或 CC Switch 本机界面填写。
8. CC Switch 模型转换只能使用工具包内置本地代理的精确 gpt-5.5 -> deepseek-v4-pro 路由。
9. 禁止使用 Codex 模型目录、model_catalog_json、无条件 body 覆盖或外置 Node 代理。
10. gpt-5.5-mini、所有 5.6 模型、其他模型和其他 provider 必须保持原样。
11. 没有我的明确批准，不向任何服务器或共享目录复制成品。

按下面顺序执行：

一、确认首次安装条件
1. 检查本机是否已有项目注册表、配音工作区、旧版安装包、同名七个 Skills、配音任务看板和本工具使用过的 CC Switch provider。
2. 如果发现需要保留的旧环境，停止首次安装，报告发现的版本和路径，并读取 docs\v2.1更新公告.md 改走升级流程。
3. 检查 Windows、PowerShell、Codex 完全访问、Python 3.10 或更高版本、Windows Python Launcher 和 ffmpeg。
4. Git 不是必需条件；没有 Git 时使用本机 ZIP。缺少 Python 或 ffmpeg 时，先报告缺失项，只从官方来源或 winget 安装所需依赖，不安装无关软件。
5. 检查系统盘和所选工作区磁盘空间。工作区必须是本机固定磁盘路径。

二、取得并验证 v2.1
6. 如果使用 ZIP，解压到本机普通目录，并确认最外层能看到 package、docs、tests、README.md 和 VERSION。
7. 如果使用 Git，克隆公开仓库到本机普通目录，切换 develop/v2.1，并记录实际 Git HEAD。
8. 完整读取 README.md、package\START-HERE.md、package\INSTALL.md、package\API与CCSwitch配置.md、docs\首次安装说明.md 和 docs\配音工具详细使用手册.md。
9. 检查安装包不存在 __pycache__、pyc、数据库、真实密钥、生产视频、MP3 或用户任务状态。
10. 在任何安装动作前运行仓库离线测试和 package\scripts\validate_package.py 能执行的预检部分。发现损坏、密钥或数据库立即停止。

三、确认工作区和第一个项目
11. 如果我已经给出工作区路径和项目名，原样使用；缺少时只询问：
   - 本机工作区绝对路径。
   - 第一个项目名称。
12. 工作区根目录用于管理多个项目，不要把项目直接建到安装包目录。
13. 创建前向我回显最终工作区路径和项目名；不得自行更换盘符、翻译或缩写项目名。

四、安装程序和七个 Skills
14. 在安装包根目录运行：
powershell -ExecutionPolicy Bypass -File ".\package\install.ps1" -WorkspaceRoot "<本机工作区绝对路径>" -ProjectName "<第一个项目名称>"
15. 真正首次安装不要添加 -Force。若脚本发现同名 Skill、程序或项目冲突，停止并报告，不能覆盖未知文件。
16. 安装必须完成：
   - 七个 Codex Skills。
   - 多项目工作区和项目注册表。
   - 第一个项目的四个主要目录与旧工具目录联接。
   - 隐藏 .codex 任务索引。
   - 配音任务看板及快捷方式。
   - Seedance API配置工具及快捷方式。
   - 工具包内置 CC Switch。
17. 确认安装没有创建或依赖 D:\codex-board，没有调用网络生成 API，也没有上传媒体。

五、配置 Seedance API
18. 打开桌面“Seedance API配置工具”，让用户在本机界面选择项目和 test版/正式版并填写一份或多份 API Key。
19. 不读取输入框内容，不在聊天、日志或最终报告中显示密钥。
20. 用户确认填写完成后，检查项目 apis 目录、api_pool 索引和当前配置文件存在；只能报告线路、配置数量和不可逆指纹。
21. 本步骤只验证配置文件结构，不发送测试生成请求。

六、配置 CC Switch
22. 打开 CC Switch，让用户在本机界面创建或选择一个 Codex provider，填写 API 地址和密钥并设为当前 provider。
23. 用户确认保存完成后，读取 package\API与CCSwitch配置.md。
24. 先运行：
py -3 package\scripts\configure_ccswitch_model.py --dry-run
25. dry-run 必须明确显示当前 provider 和精确 gpt-5.5 -> deepseek-v4-pro，且声明其他模型、provider、API Key 和 base_url 不变。
26. 确认范围后，备份 cc-switch.db，使用 SQLite 单事务在线写入 provider.meta.localProxyRequestOverrides.modelRoutes.gpt-5.5。
27. 验证 gpt-5.5-mini、全部 5.6、其他模型和其他 provider 未变化，PRAGMA integrity_check 必须为 ok。
28. 不得在 ~/.codex/config.toml 写入 model_catalog_json，不得使用无条件 body 覆盖或启动外置代理。

七、初始化六个 Codex 任务
29. 把当前入口任务命名为“理解文本与任务”。
30. 读取项目 .codex\03_codexchat对应表.json 和 manage-voice-production 的 chat-workflow 规范。
31. 运行 manage_chat_workflow.py bootstrap-status。未就绪时，根据返回的 chat_creation_contracts 创建“提示词、生成、监控、拉回、记录”五个独立任务。
32. 创建每个任务时必须显式指定合同中的模型和 reasoning_effort，不能使用界面默认值。
33. 每个新任务的第一条消息固定为：
这个对话开启完全访问，不需要问我要任何的批准。
34. 这句话只是初始化说明，不能代替实际权限。每个任务必须亲自运行 verify-access，通过无害写入、读回和删除探测，再用 register 登记真实 thread ID、实际模型和实际 reasoning_effort。
35. 六个任务 thread ID 必须互不重复。所有验证通过并且 bootstrap-status 返回 ready=true 前，不得开始生成。
36. “记录”任务是单向终止阶段；其他阶段反馈到“理解文本与任务”。

八、最终验证
37. 运行 package\scripts\validate_package.py，验证安装包、工作区、项目、七个 Skills、看板、API 工具、CC Switch 功能标记和旧目录联接。
38. 再运行完整离线回归、缓存/数据库/密钥扫描和 Git 状态检查；不得调用付费 API。
39. 打开配音任务看板，确认能识别工作区和第一个项目。不要创建生产任务用于测试。
40. 最终报告必须包含：v2.1 版本、Git HEAD（如有）、安装包路径、工作区路径、项目路径、七个 Skills、看板和 API 工具位置、CC Switch EXE 哈希、数据库备份路径、精确路由检查、完整性检查、测试结果和仍需用户完成的操作。
41. 如果本次安装了 CC Switch 程序，完成当前工作后提示用户手动重启一次 CC Switch；安装新 Skills 后提示用户重启一次 Codex。
42. 不得把 API Key、完整 provider settings 或其他密钥写入最终报告。
```

## 首次安装完成标准

- 工作区和第一个项目位于用户指定的本机路径。
- 项目注册表和四个主要目录存在。
- 七个 Skills、看板和 Seedance API 配置工具已安装。
- API Key 只存在本机私有配置，不出现在聊天和日志。
- CC Switch 仅保存精确 `gpt-5.5 -> deepseek-v4-pro` 内部路由。
- 六个 Codex 任务使用真实 thread ID、指定模型和实际权限验证。
- 安装和验证没有调用付费 API、上传素材或写入服务器。
- 安装包验证与完整离线回归通过。
