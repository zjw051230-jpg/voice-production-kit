# 配音工作流工具：从 v2.0 升级到 v2.1

> 历史更新公告。v2.2 起环境工具已迁移到独立 `env4BC`。

发布日期：2026-08-11  
适用对象：已经安装并使用 v2.0 的 Windows 用户
GitHub：<https://github.com/zjw051230-jpg/voice-production-toolkit4bingchuan>  
更新分支：`develop/v2.1`

## 这份报告解决什么

这不是新电脑首次安装说明，而是把现有 v2.0 环境升级到 v2.1。升级必须保留原工作区、所有项目、素材、任务 JSON、视频、MP3、API 配置、日志、地址索引和隐藏任务记录。

v2.1 的主要变化：

- 强制使用“理解文本与任务、提示词、生成、监控、拉回、记录”六个独立 Codex 任务。
- 每个任务必须登记真实 thread ID、指定模型、思考程度和完全访问验证结果。
- 主任务派发后停止并等待反馈；目标忙碌时每 5 分钟重试，禁止同一任务并发两项工作。
- “记录”任务改为单向终止阶段，不向主任务回报。
- 只有整批满足“成功数 + 失败数 = 总数”后才允许拉回。
- 看板增加成功、失败、运行中、已下载和终态进度。
- CC Switch 从 v2.0 的 `5.5 -> dpskv4` 模型目录映射，迁移为内置本地代理中的精确 `gpt-5.5 -> deepseek-v4-pro` 路由。

## 升级边界

1. 不要在聊天中发送 API Key。
2. 不得删除或覆盖现有项目资料与生产成品。
3. 不得创建或修改 `D:\codex-board`。
4. 不得向服务器、UNC 路径或网络共享目录复制文件。
5. 升级期间不得调用 Seedance 或其他付费生成 API。
6. CC Switch 正在承载当前 Codex 对话时不得主动停止。
7. 只能迁移当前 Codex provider 中 v2.0 创建的精确 `5.5 -> dpskv4` 条目；其他模型、provider、API Key 和 `base_url` 必须保持不变。
8. 现有项目有正在执行的生成、监控或拉回任务时，先停止升级并等待任务结束。

## 升级完成标准

Codex 的最终报告必须确认：

- 现有工作区和全部项目保持原路径。
- 项目素材、任务 JSON、视频、MP3、日志和索引未变化。
- v2.1 的七个 Skills、看板和 API 配置工具已安装。
- 六任务状态表已迁移，真实模型、权限和 thread ID 仍需按门禁验证，不能伪造完成。
- 当前 provider 的旧 `5.5 -> dpskv4` 条目已安全迁移。
- 新 `gpt-5.5 -> deepseek-v4-pro` 内部精确路由已保存。
- 其他模型、provider、API Key 和 `base_url` 未变化。
- 数据库备份存在且 `integrity_check: ok`。
- 完整回归与安装包验证通过。
- 明确说明是否需要用户手动重启一次 CC Switch。
