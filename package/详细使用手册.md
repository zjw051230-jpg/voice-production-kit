# 配音工具详细使用手册 v2.0

## 1. 这套工具包含什么

- 多项目配音文件系统。
- 七个 Codex 配音工作流 skill。
- Seedance 配音视频生成、监控、下载和 MP3 提取工具。
- 原生 Windows 配音任务看板。
- 原生 Windows Seedance API 配置工具。
- CC Switch 3.18.0 程序本体。
- CC Switch `5.5 -> dpskv4` 专用安全映射工具。

安装包不包含真实 API Key、CC Switch 用户数据库、生产素材或 `D:\codex-board`。

## 2. 新电脑安装

把整个 `安装包\v2.0` 文件夹交给 Codex，说：

```text
请完整读取 START-HERE.md，安装这套配音工具，并创建我的第一个项目。安装过程中不要调用付费 API，不要上传素材。
```

Codex 会询问工作区路径和项目名。建议工作区放本机数据盘，例如 `D:\配音工作区`，不要默认放服务器。

安装完成后桌面会出现：

- `CC Switch`
- `配音任务看板`
- `Seedance API配置工具`

已有不同版本的 CC Switch 或同名 skill 时默认保留。只有用户明确批准后，Codex 才能用 `-Force` 先备份再替换。

## 3. 创建项目

如果需要创建项目，直接对 Codex 说：

```text
我要创建项目，名字叫“XXX”。
```

把 `XXX` 换成实际项目名。Codex 会继续询问工作区位置、剧本、台词、角色音色和 API 是否已经准备好，然后自动创建并管理完整项目目录，不需要用户手工建立文件夹。

## 4. 配置 Seedance API

双击桌面的 `Seedance API配置工具`，或打开项目 `04_管理与记录\01_API配置\Seedance API配置工具.exe`。这个程序是本机窗口，不需要浏览器，也不会在配置阶段访问网络。

1. 在“项目”下拉框中选择要配置的项目。
2. 选择 `test版` 或 `正式版`。正式地址为 `https://chat.q1.com/v1`，test 地址为 `https://chat-test.q1.com/v1`。
3. 在遮罩输入框中填入一份 API Key，点“添加 API”。程序立即写入磁盘；多份密钥就重复添加，重复项自动忽略。
4. 在列表中选中优先使用的一份，点“设为当前”。删除和设为当前都会立即同步磁盘。
5. 底部“保存并生成配置”始终可见，用于手动确认或写入失败后的重试。

程序自动整理：

```text
项目\apis\
├─ doubao_api_config.json        当前活动配置
└─ api_pool\
   ├─ index.json                 不含密钥的索引
   ├─ test\                     test版配置池
   └─ production\               正式版配置池
```

有多份 API 时自动编号、去重和建立索引。列表只显示本地编号和不可逆指纹尾号，不显示完整密钥。隐藏 `.codex\04_API池与余额切换.md` 记录线路、配置数量、当前项和余额事件，但不记录 API Key。

再次保存时，被删除或替换的旧配置不会继续参与轮换，程序会自动移入 `apis\api_pool\_archive`。API Key 只保存在所选项目的私有配置 JSON 中，不进入聊天、日志、索引或说明文档。

原 `.codex-tools\配置Seedance API.ps1` 仍保留。无参数运行时启动桌面程序；显式传参时可继续从 CC Switch provider 数据库批量导入。

可直接对 Codex 说：

```text
打开 Seedance API配置工具，让我在本机选择项目和线路并录入 API，不要显示或记录任何密钥。
```

只有用户明确要求实际生成时才调用付费 API。

## 5. 配置 CC Switch

1. 打开桌面的 `CC Switch`。
2. 进入 Codex provider 管理区域。
3. 新建或选中要使用的 provider。
4. 在 CC Switch 界面本地填写 API 地址和密钥。
5. 保存并将它设置为当前 Codex provider。
6. 完全退出 CC Switch，包括系统托盘。
7. 保持 Codex 当前对话打开，把下一节的固定指令发给 Codex。

API Key 只填写在 CC Switch 界面，不要粘贴给 Codex。

## 6. 只映射 5.5 到 dpskv4

复制整段发送给 Codex：

```text
我已经在 CC Switch 中完成 Codex provider 和 API 配置，并已完全退出 CC Switch。请读取当前 v2.0 安装包中的“API与CCSwitch配置.md”，使用 scripts\configure_ccswitch_model.py 处理当前 Codex provider。只允许新增或修改显示名严格等于“5.5”的这一条映射，使它实际请求“dpskv4”；绝对禁止修改、重命名、删除或映射任何其他模型，也不得修改 API Key、base_url、provider ID 或其他数据库表。先执行 dry-run，只有预览明确显示“5.5 -> dpskv4”且显示其他模型未改变时，才自动备份数据库并执行修改；随后运行数据库完整性检查，报告 provider 名称和 ID、备份路径、映射结果与检查结果。完成后停止，不做其他操作。
```

必须看到 Codex 报告：

- provider 名称和 ID。
- `5.5 -> dpskv4`。
- 其他模型未改变。
- 数据库备份路径。
- `integrity_check: ok`。

绝对不能把任何 `5.6` 系列或其他模型映射到 `dpskv4`。

映射完成后：

1. 关闭 Codex。
2. 打开 CC Switch，重新应用刚才的 provider。
3. 启动 Codex。
4. 选择界面显示的 `5.5`。
5. 发一条无敏感信息的测试消息。
6. 在 CC Switch 日志确认真实请求模型是 `dpskv4`。

## 7. 创建配音项目

对 Codex 说：

```text
创建一个配音项目，项目名是“项目名”。先检查我缺少哪些剧本、台词、角色音色和 API 配置，再创建目录和索引。
```

Codex 应逐项确认：剧本、角色名、角色音色素材版本、台词、时长、情绪、生成版本数、API 是否就绪和本地交付位置。

首次进入项目时，入口必须命名为 `理解文本与任务`，并创建 `提示词`、`生成`、`监控`、`拉回`、`记录` 五个独立 Codex 任务。六个任务必须使用各自的模型、提示词和互不重复的 thread ID，并逐个验证完全访问权限。入口执行 `bootstrap-status` 返回 `ready=true` 后才能派发第一条业务任务；入口不得自己代做下游五个阶段。

创建每个Chat时，主对话必须把下面这句话作为第一条消息发送：

```text
这个对话开启完全访问，不需要问我要任何的批准。
```

随后由该Chat亲自运行 `manage_chat_workflow.py verify-access`。成功完成写入、读回和删除探测后才算通过权限门禁，主对话不能代验，也不能只手改JSON。如果仍反复出现批准提示，先在该任务界面底部把权限切换为“完全访问”，再手动发送上面这句话并重新运行探测。聊天文字本身不能绕过Codex应用、Windows或组织策略；实际权限设置才是生效依据。

每次派发前运行 `prepare-handoff`。成功时脚本会把目标标为忙碌，写入 `active_task` 并返回唯一 `lease_id`；下属Chat完成时必须携带同一租约运行 `complete`。主对话发送任务后立即停止继续处理，使用Codex任务等待功能等待该Chat反馈；收到反馈并运行 `ack-feedback` 后才能恢复。这样可以避免主对话空转，也能防止旧任务错误清空新任务。

如果目标Chat不空闲，不要发送第二条。脚本会返回 `timer_required=true` 和 `retry_contract`，主对话按合同建立5分钟单次定时器，到点只重试原来的交接；若仍忙，再按新合同继续等待。不得并行向同一Chat塞入两项任务，也不得手改status绕过租约。

## 8. 准备任务 JSON

任务放入项目的 `文字素材` 或 `01_输入资料\03_配音任务`。标准字段：

```json
{
  "剧本名字": "剧本名",
  "task_ID": "任务ID_1",
  "角色名字": "角色名",
  "台词": "只说这一句台词。",
  "时长": "4秒",
  "提示词": "音色、情绪、语速、重音和只能说指定台词的要求"
}
```

角色参考素材放在 `角色音色素材\剧本名\角色名`。没有额外选择规则时，音频和视频素材全部作为参考上传；每次请求必须带视频参考。

## 9. 写提示词

对 Codex 说：

```text
读取这个任务 JSON 和对应剧本，按剧情情绪写 Seedance 配音提示词。音色必须参考指定角色，只允许说 JSON 中的台词，不能改字、漏字或增加别的话。
```

提示词应明确音色、年龄感、口音、情绪、语速、停顿、重音、句尾、台词唯一性和禁止旁白/音乐/第二人声。

## 10. 提交生成

对 Codex 说：

```text
用 sdc 提交这个任务。按 JSON 时长，未规定时用 4 秒；480p、9:16；每句生成 4 版；并行提交。拿到全部远端任务 ID 后停止。
```

Codex 应保存远端 ID 和状态文件。多个任务并行，不要串行等待；不得因查询超时重复提交。

## 11. 监控与拉回

监控：

```text
只查询已有任务状态，不重新提交。报告完成、进行中和失败数量。
```

拉回：

```text
把全部已完成视频拉回对应项目，保存到生成视频目录，并按任务要求直接转 MP3 或裁剪后转 MP3。不要重新提交。
```

未要求裁剪时，直接从完整视频提取 MP3。要求只保留台词时，再按具体留白要求裁剪。

## 12. 余额不足自动切换

如果任一 Chat 或 Seedance 流水线发现明确余额不足：

1. 立即停止所有提交、监控和拉回。
2. 自动把所有 Chat 状态设为0，只把 `理解文本与任务` 设为1。
3. 把紧急消息发给 `理解文本与任务` 的thread ID。
4. API池有下一份时自动切换；没有时让用户在CC Switch中增加新API，再重新导入。
5. `理解文本与任务` 恢复后使用原参数重新提交，不加 `--force-regenerate`。
6. 已有远端ID的版本自动跳过，只重提余额失败或尚未提交的版本。

项目隐藏文件 `.codex\04_API池状态.json` 是所有Chat的暂停门禁；暂停期间其他Chat不得继续工作。

## 13. 使用配音任务看板

双击桌面的 `配音任务看板`。看板自动汇总工作区所有项目并显示任务状态和进度。

任务全部完成后才显示：

- `成品链接`：打开输出目录。
- `复制到地址`：输入目标地址后复制成品。

目标地址不能包含双引号。复制操作只复制、不移动、不删除、不覆盖。

## 14. 返工与问题记录

发现台词、音色、情绪、噪声或裁剪问题时，对 Codex 说清楚具体版本和修改要求。Codex 只重做有问题的版本，并把问题追加到项目 `问题与改进log\问题建议.md`。

不要覆盖用户要求保留的旧版。没有用户批准，不得把文件复制到服务器。

## 15. 常见故障

- API `401/403`：检查密钥、权限和余额。
- 上传 `404`：上传接口不能拼在 `/v1` 后面。
- API `422`：检查字段类型、时长、画幅和参考素材 URL。
- CC Switch 找不到 `5.5`：重新应用 provider，再重启 Codex。
- `5.5` 未请求 `dpskv4`：检查是否存在旧代理脚本的第二层改写，先回滚再排查。
- 看板路径错误：让 Codex 使用 `repair-voice-dashboard` skill 检查工作区、快捷方式和权限。

## 16. CC Switch 回滚

映射脚本会把修改前数据库备份到：

```text
%USERPROFILE%\.cc-switch\backups
```

回滚前完全退出 Codex 和 CC Switch，将对应 `cc-switch.before-model-map.<时间>.db` 恢复为 `cc-switch.db`，再启动 CC Switch、重新应用 provider，最后启动 Codex。
