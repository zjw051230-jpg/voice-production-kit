# 剧本转语音提示词 JSON

把剧本上下文转成逐句、可独立使用的 Seedance 人声生成任务，并可靠地保存为 JSON。

保存或覆盖六字段任务 JSON 后，若项目存在 `.codex`，必须调用 `$manage-voice-production` 中的 `scripts/sync_task_manifest.py` 更新素材状态、台词位置索引和逐句任务清单，再交给生成流程。

## 启用原则

- 用户要求生成或修改任何音频、语音、配音、音色克隆相关提示词时，必须使用本 skill。
- 用户未明确说“提示词”，但要求把剧本或台词整理成可供语音生成使用的文本或 JSON 时，也必须使用。
- 其他涉及台词拆分、表演指导、时长估算或语音任务格式校验的场景，可按需要使用。

## 工作流程

1. 获取用户提供的 `task_id`、剧本名字和剧本内容或剧本文件。把 `剧本名字` 视为 `角色音色素材` 下的一级分类目录名，必须与实际目录完全一致；不能仅凭剧情标题猜测不同的分类名。
2. 在拆台词前完整读取剧情总览、角色小传、目标场景及相邻台词。严格执行 [references/overview-to-prompt.md](references/overview-to-prompt.md) 的取证、冲突处理和上下文卡流程，不得只搜索目标台词后直接写提示词。
3. 建立台词清单，识别真正说出口的内容。排除场景说明、动作、镜头、内心独白和玩法说明，除非文本明确要求将其作为旁白生成。逐项核对角色、台词原文、出现顺序及男女主变体，避免漏句、重句或错配角色。
4. 每一句独立生成一个任务。保留原台词文字与标点，不擅自润色、合并或补写。只有原文或用户明确要求男女玩家双版本时，才为同一句生成多个角色版本。
5. 为每句建立内部上下文卡：触发事件、当前场景、说话对象、角色此刻已知信息、未知信息、直接目的、表层情绪、深层心理、情绪克制方式、节奏依据。所有表演指令必须能回溯到该卡片。
6. 推断时遵守角色知识边界：只能使用该句发生前角色已经知道或正在观察到的信息；不得把总览中的后续真相、作者说明或其他角色秘密写进当前心理。推断与原文冲突时以明确台词和正式剧情为准；信息不足时使用低断言表达，不虚构关键事实。
7. 遇到短句（通常 8 个汉字以内、感叹、称呼、判断或命令），不要因为文本短而写成空泛提示词。用前后剧情补足触发事件、潜台词、起句状态、关键词重心和收句状态；补的是表演心理，不是补说新台词。
8. 按“音色锁定 → 场景触发 → 对象与已知信息 → 目的与潜台词 → 情绪和节奏 → 台词白名单 → 纯净输出”的顺序写成一段自然中文。音色锁定时，参考音视频是声音本身的唯一来源；只要求严格复刻，不用文字重新规定年龄、地域、口音、音高、共鸣、声线厚薄或性别气质。提示词只控制该角色这一次的情绪、意图、语速、停顿、重音和收句。删除重复信息和互相冲突的形容词，让每条指令形成清楚的因果链。
9. 估算建议时长并编写提示词。严格遵守 [references/output-spec.md](references/output-spec.md) 的字段、时长和提示词规则；把“仅允许目标台词完整出现一次”写成最高优先级的硬约束，而不是普通建议。
   每条提示词必须原样包含 [references/output-spec.md](references/output-spec.md) 中的“固定硬约束段”，把其中 `<目标台词>` 替换为该任务的完整台词。
10. 生成 UTF-8 JSON 数组，保持台词出现顺序。每项只含六个字段：`剧本名字`、`task_ID`、`角色名字`、`台词`、`时长`、`提示词`。第 x 项的 `task_ID` 必须为 `<task_id>_<x>`，x 从 1 开始且不补零。
11. 将草稿 JSON 放在临时工作目录，通过以下命令校验并保存：

   ```powershell
   python "<skill-directory>\scripts\save_voice_prompts.py" --task-id "<task_id>" --input "<draft.json>"
   ```

   将 `<skill-directory>` 替换为本 `SKILL.md` 所在目录的绝对路径。
12. 对照原始台词清单做双向完整性复核：每条原台词都有且只有一个预期任务，每个任务都能定位到原文；再确认脚本返回的文件路径和任务数。最终仅向用户报告已保存的文件、任务数和必要假设；不要在聊天中重复整份长 JSON，除非用户要求。

## 不完整输入

- 未提供 `task_id`：先完成可完成的解析，但不要写入最终目录；向用户索取 task ID。
- 未明确提供剧本名字：先检查当前项目 `角色音色素材` 兼容路径下已有分类目录；只有唯一明确匹配时才采用，否则向用户确认，不要跨项目搜索或把剧情标题擅自当成素材分类。
- 只提供总览而未明确范围：处理总览中所有明确标注的台词，并告知采用了该范围。
- 角色名称含糊：优先采用剧本中的显示名；仅在上下文明确时把“我/主角”规范成具体名字。
- 同一句台词由玩家男女声二选一：若剧本明确支持两种玩家性别，分别生成“玩家男声”和“玩家女声”；否则只生成剧本明确指定的版本。
- 输出文件已存在：保存脚本会拒绝覆盖。先比较内容；只有用户明确要求替换时才使用 `--overwrite`。

## 质量检查

- 确保一个对象只对应一个角色的一次发声。
- 确保所有对象的 `剧本名字` 一致、可安全作为单层 Windows 目录名，并与音色素材分类一致；第 x 项的 `task_ID` 严格等于 `<task_id>_<x>`。
- 确保 `台词` 与提示词中引用的台词完全一致。明确声明该句是唯一发声白名单，只完整说一次；禁止开场白、称呼、回应、解释、语气词、旁白、重复、改写、漏词、续写及第二句话。
- 确保明确写出参考音视频只用于复刻音色与说话习惯，绝不继承或复述参考素材里的原台词、口头禅、旁白和背景人声。
- 确保音色指令明确“严格复刻参考音视频的原始声音、音色和自然说话习惯，参考决定声音本身”；禁止再指定或改造年龄、地域、方言、口音、音高、共鸣、声线厚薄、性别气质或少年感。只用情绪、目的、节奏、重音和收句控制本句表演。
- 确保每条有可追溯的心理锚点：触发事件、角色此刻的认知或担心、对话目的，以及情绪外露或克制方式。
- 确保没有使用角色在当前时点尚不知道的后续剧情、秘密或上帝视角结论。
- 确保提示词形成因果顺序：发生了什么 → 角色如何理解 → 想对谁产生什么影响 → 因此如何说。
- 确保短句另有具体表演支点：起句状态、关键词重心、收句状态或停顿；不因短而只写“自然说一次”。
- 确保完整目标台词在提示词中只出现一次。节奏说明只引用关键词，不得再次粘贴完整台词。
- 确保表演描述由剧情支持，并包含语速、重音或停顿指引。
- 确保提示词要求台词前后各约 0.5 秒安静，并排除旁白、第二人声、音乐、音效和环境噪声。
- 确保文件名中的 `N` 等于 JSON 数组长度。
- 对照原始清单核对任务总数、顺序、角色、男女版本和台词标点，确保不漏、不重、不串场。
- 使用 JSON 解析器验证，不把 Markdown 代码围栏写入文件。
