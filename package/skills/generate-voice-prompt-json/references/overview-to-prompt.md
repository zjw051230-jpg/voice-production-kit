# 从剧情总览到语音提示词

## 证据优先级

出现冲突时依次采用：

1. 用户本次明确要求与指定台词。
2. 标为正式、原稿或最终版的目标场景内容。
3. 角色小传和已确认人物关系。
4. 相邻台词、动作与场景描述。
5. 剧情补全、推测或隐藏线索。

不得用低优先级推测覆盖明确原文。发现无法调和的角色、台词或时间线冲突时停止写最终文件并说明问题。

## 总览取证

先完整理解总览结构，再为目标台词收集最小充分上下文：

- 该句前最近的触发事件或上一位说话者。
- 该句后的即时结果，用于判断说话目的是否达成。
- 角色在当前时间点的身份、关系、稳定性格和创伤。
- 当前场景的危险程度、距离、隐私性和行动压力。
- 原文明确标注的情绪、对象、重点、原因和禁止演法。
- 该角色当前已知与未知的信息。

只把会改变声音表现的信息写入最终提示词，其余用于内部判断。

## 单句上下文卡

每条台词在写提示词前先在内部补全以下项目：

```text
原文位置：章节 / 场景 / 顺序
角色与对象：谁对谁说，关系与距离
触发事件：上一秒发生了什么
当前已知：角色能确定什么
当前未知：角色仍在猜测什么
直接目的：希望对方知道、停止、相信或行动什么
表层情绪：角色允许对方听见的情绪
深层心理：角色试图隐藏或压住的情绪
声音落点：语速、音量、气息、停顿、重音、句尾
禁止偏差：最容易演错成什么
```

卡片不写进 JSON，但最终提示词必须覆盖其中与声音有关的内容。

## 因果转换

不要直接把“人物很焦急”搬进提示词。按以下链条转换：

```text
剧情事实 → 角色理解 → 对话目的 → 心理冲突 → 可听见的声音表现
```

示例：

```text
门后传来怪物声 → 角色判断时间不多 → 想让同伴立即后退 →
自己也害怕但必须镇定 → 起句快、关键词有力、句尾咬住，不尖叫
```

## 准确性检查

- 不把旁白知道的真相写成角色已知事实。
- 不把后续揭晓的身份、背叛、死亡或线索提前写入当前心理。
- 不把“也许、好像、可能”演成确定答案。
- 不因角色稳定性格覆盖当前场景，例如幽默角色在生死判断时仍可严肃。
- 不把剧情补全内容当成原稿硬设定；需要使用时采用低断言表达。

## 完整性检查

生成前建立台词清单，生成后逐项回勾：

- 原始行数与任务数是否一致。
- 角色、台词、标点、顺序是否一致。
- 男女主、年龄或语言版本是否按用户要求展开。
- 同一句是否误重复，不同句是否误合并。
- 每条是否都有音色、场景、对象、触发、已知/未知、目的、心理、节奏、白名单和纯净输出约束。
